# Étape 24 : pilote de dix fonctions avec pools internes ou explicites

Projet validé après fermeture et réouverture : `archive:ghidra_thumb_inline_pilot_scoped/step9.gpr`, programme `gs_us_map.elf`. **2 556 fonctions**, rappel ROM **2 186/2 253 = 97,03 %**, 67 entrées absentes. Récupération guidée par le source, baseline REA inchangée.

Le nouveau `plan_thumb_inline.py` traite seulement les instructions Thumb déjà admises, les `.word`, l'alignement à quatre octets avec remplissage nul et les flush `.pool`/`.pool_aligned`. Les slots des pseudo-LDR doivent décrire exactement le pool suivant. Les LDR explicites doivent viser le label source à l'adresse décodée de la ROM. Chaque mot déclaré doit être lu par un LDR démontré, et son expression doit correspondre aux quatre octets de ROM. Les labels locaux portant une adresse vérifient aussi la disposition calculée.

Le graphe source doit atteindre toutes les instructions et ne peut tomber dans les données ou le remplissage. Sauts directs décodés contre la ROM, appels supposés revenir, aucun branchement calculé autre qu'un retour BX LR ou pop/BX adjacent. Les macros d'appel calculé, opérations PC et autres cas restent exclus. Un contrôle séparé des 45 layouts acceptés confirme les plages de code disjointes des pools ; quatre corruptions d'opcode, de mot, de branche et de fallthrough sont rejetées (`thumb_inline_planner_checks.json`).

Le plan exporte des `body_ranges` non contigus et un schéma `thumb-inline-v1`. Les scripts d'export/application et le vérificateur comparent exactement ces corps, au lieu de supposer une plage unique. Les données internes doivent être hors de toutes les plages de code. Les invariants sur les anciennes annotations ne changent pas. Une régression sur le plan call_via précédent confirme l'application idempotente après cette extension.

Sept retours RETURN reconnus sur copie d'analyse puis appliqués sur copie propre. Toutes les anciennes fonctions, instructions, données définies, octets et permissions conservés. Les dix décompilations terminent sans avertissement. Fermeture/réouverture : mêmes snapshots, preuves de pools et C ; deuxième passage sans modification.

Func_fa350 tronque l'index à seize bits, utilise deux tables et conserve les conditions des deux chemins d'appel.
